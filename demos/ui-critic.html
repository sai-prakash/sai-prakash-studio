UI Critic: a small model proposes, code verifies.

Paste a UI, or pick a sample. SmolVLM-256M (in your browser, via WebGPU) describes what it sees and proposes defects. Deterministic checks then verify each proposal against the approved palette, states and layout — because a 256M model alone should never be the verdict.

3 · What code verifies (deterministic)


The verifier reads the agent SVG's own fills, opacities and button positions and checks them against the approved palette, state and layout for that sample. For a real screenshot this step would sample pixels instead — see README for that next step. The verifier never reads the model's text, so it cannot agree with it by accident.











4 · Live model (experimental, opt-in)


Honest warning: browser SmolVLM support is fragile. Public forum reports show the Transformers.js SmolVLM path failing at the processor step even when the model loads. This prototype therefore loads the model only when you ask, shows its real error verbatim if it fails, and never breaks the precomputed examples. Test in desktop Chrome/Edge with WebGPU. Safari has no WebGPU — expect the WASM path to be very slow or to fail.

How it fits the portfolio


Find (Design System Search) → Prove (Evidence Finder) → Check (Agent UI Check, similarity + pixels) → Understand (this critic, vision + verifier). Same thesis throughout: useful AI shows evidence, and a small model proposes while code decides.
